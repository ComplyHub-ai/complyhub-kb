- **Already-broken `packaging_rules` records are stuck, not just "click import again."** The "Import Units and Packaging Rules" button is disabled once `q1_tas_builder.is_extracted = true`, regardless of whether the saved data is actually complete. The old (pre-fix) extraction code set `is_extracted = true` even when it silently omitted `unitList`, so any record broken before the fix (2 Jul 2026, PR #109) has its import button permanently greyed out in the UI. Recovery needs either (a) a brand new TAS build for that qualification, or (b) someone manually resetting `is_extracted` back to `false` on the specific stuck record (a data-fix, not a UI action) before the button re-enables. Confirmed condition: `src/components/tas/builder-sandbox/ElectivesSection.tsx:1724` — `disabled={importingTGA || isExtracted}`.

- **Separate bug found during QA (2 Jul 2026): "Create New TAS v2" Step 2 (Configure TAS) renders completely blank.** Reproduced twice, via both routes into Step 2 — the normal "Continue to Configure" path (`advanceFromStep1`, `src/pages/tas/engine/index.tsx:837`) and the "Continue with Variation" path (`handleVariationConfirmed`, same file `:898`). Both only call `setStep(2)` and never touch `selectedProduct`, so by static reading the Step 2 block (`:1412`, gated on `step === 2 && selectedProduct`) should render a full form (TAS Name, Delivery Mode, Stream) — but in practice nothing renders except the stepper header and Back/Cancel/Next footer, and "Next" does nothing (almost certainly just `isStep2Valid()` failing because the required TAS Name field never got a chance to render/populate). No red error in the browser console when reproduced (checked directly) — only an unrelated `aria-hidden` accessibility warning — so this isn't an uncaught JS exception, or one that's being logged. Not yet diagnosed further; needs someone to inspect actual React state at runtime (React DevTools) rather than static code reading, since the code as written contradicts the observed behaviour. Worked around during QA by using an existing build's Units tab directly instead of creating a new TAS.
